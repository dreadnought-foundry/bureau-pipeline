## Findings for whoever reads this next

- The daily pass is rate-limited by GitHub in many passes: of the 107 passes that printed the note line, a share printed `0 proof record(s) … oldest none · not read (rate limit): …` with every card skipped, and others printed a lower N (2, 3, 4) than the card count. The note is honest about it, but the count in a rate-limited pass is not the day's count. Only the first fully read pass of a PT day posted comments here (2026-11-02 00:12 PT, 2026-11-03 01:11 PT).
- The replay of the whole agent-bureau board spends 86 Linear requests and takes about six minutes, so a proof run's cap of 40 cannot cover that command and the Linear reads the second row asks for in the same run. The card's Linear reads (rows 2, 3, 5 and 6) need a larger `PROOF_LINEAR_REQUESTS` or a replay that reads fewer cards.
