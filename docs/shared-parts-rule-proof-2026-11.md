## Beyond the criteria

The card assumed that every bureau-pipeline card is an `agent:devops` card. That does not hold in this window. Of the 91 build runs, 29 assembled context as `engineer`, and each printed the two `none` lines. One was run 41973215800 for DRE-9224: `2026-11-05T05:19:10.5624404Z design-parts: none — no .github/bureau/design-system.json and no design/LOCK.json`. The other 9 runs printed no `assembled … for role:` line, which means they did not reach that step. The role-scope row still holds, because the 53 `devops` runs are what it reads.

`standards/design-system.md` § "The parts-check line" says every critic verdict on a pull request that changes a UI file, in a repo whose design system exists, carries exactly one parts-check line. In agent-bureau that held on fewer verdicts than it missed. All 222 agent-bureau pull requests opened after the release were read, along with their 352 critic verdicts, through 2026-11-05 00:00 PT. A UI file here means a kept `.tsx`, `.jsx`, `.vue` or `.svelte` file, as `design_parts.UI_EXTENSIONS` defines it.

- 69 of those pull requests change a UI file, and they carry 134 critic verdicts. Only 29 of those verdicts carry a `Parts check:` line.
- On 8 of the 69, every verdict carries one: #4582, #4583, #4600, #4621, #4626, #4678, #4690 and #4720.
- On 18, some verdicts do and some do not. #4554 is one of them.
- On 43, no verdict does.
- On the other side, 3 of the 218 verdicts on pull requests with no UI file carry a line the section says they should not: `Parts check: not applicable (no UI files in the diff).` (#4527), `Parts check: does not apply — the diff changes no UI component files.` (#4531) and `Parts check: does not apply.` (#4628).

The run logs read here show the review itself firing where it should. The miss is in the critic's verdict text, and this record names it for whoever reads it next. It is not a row on this card.
