# PROOF record — DRE-6353: PROOF: a fix run's committed work reaches the pull request branch after its own push is refused — observed on a real pull request in bureau-pipeline (epic DRE-4911)

**Status: PASS.**

The refused-push sequence was staged on 2026-10-09 and watched end to end on pull request #854, a throwaway pull request against a throwaway base. A repository ruleset refused every push to its branch. The fix agent corrected the test, committed, and its push was refused. `Push rescue` tried both fresh mints, was refused, and uploaded `rescue-DRE-6476.patch`. The Report posted the `fix-run-committed-not-pushed` notice and left the card where it was. Thirty-eight minutes later the reconcile sweep restarted the fix loop once. The second run was refused the same way, posted the cap hold and parked the throwaway card in Triage with `needs-human`. The ruleset was then deleted, the delivery was dispatched by hand with the first run's id, and the agent's commit landed on the pull request's own branch. The critic approved that head two minutes later.
